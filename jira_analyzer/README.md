# jira_analyzer — анализ работы по данным Jira

Выгружает задачи из Jira (Server/DC, PAT-токены), считает метрики работы
разработчиков и показывает интерактивный отчёт: графики (ECharts), таблицы,
HTML-отчёт, который открывается офлайн двойным кликом, и Excel.

## Установка и запуск — без скриптов

**Linux / macOS:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m src.web.app        # web-интерфейс → http://127.0.0.1:8765
# или CLI:
.venv/bin/python main.py --project CURATOR --jira-type apache
```

**Windows (CMD / PowerShell):**

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m src.web.app   REM web-интерфейс → http://127.0.0.1:8765
REM или CLI:
.venv\Scripts\python.exe main.py --project CURATOR --jira-type apache
```

Требуется Python **3.11+**. Тестовый прогон без токена: проект **CURATOR**,
тип jira **apache** (открытый стенд Apache Jira).

## Установка и запуск — скриптами (Windows)

| скрипт      | что делает |
|-------------|------------|
| `setup.bat` | находит python, создаёт `.venv`, ставит зависимости, создаёт `.env` из шаблона. Запуск — один раз |
| `start.bat` | запускает терминал с web-интерфейсом и печатает ссылку. Требует сначала выполнить `setup.bat` |

Эквивалент скриптов руками: `python setup/start.py` (установка) и
`python -m src.web.app` (запуск).

## Web-интерфейс

Открыть http://127.0.0.1:8765 (порт меняется в `.env`, `WEB_PORT`).
Интерфейс разделён на две зоны — задачи из Jira скачиваются **один раз**
в свою папку, анализировать скачанное можно сколько угодно без обращения
к Jira.

**1 · Выгрузка задач из Jira.** Ключ проекта, тип Jira (секция `.env`:
`jira` / `jira_delta` — корпоративные, `apache` — тестовая без токена),
диапазон дат создания, лимит задач, комментарии. Кнопка «Скачать задачи»
сохраняет всё в `data/raw/<ключ проекта>/`. Повторный запуск по тому же
ключу перезаписывает папку — это и есть «обновить выгрузку». Если папка
уже содержит выгрузку из **другой** Jira — интерфейс предупредит.

Выгрузка не боится прерываний: всё пишется в `data/raw/<ключ>/_partial/`
с чекпоинтами, и только по полному успеху попадает в корень папки. Кнопка
**«⏹ Стоп»** останавливает выгрузку, сохранив прогресс; падение сети или
закрытие окна делают то же самое. При следующем запуске по тому же ключу
появится баннер: **«Продолжить»** (докачать с места остановки) или
**«Начать заново»** (стереть прогресс). Продолжить можно только с теми же
параметрами (даты, лимит, тип Jira) — иначе предлагается начать заново.

**2 · Анализ скачанных выгрузок.** Таблица того, что скачано: ключ, тип
Jira, число задач и событий, дата выгрузки. Выбери строку, собери метрики,
запусти — пересчёт идёт по файлам папки, без хождения в Jira.

**Метрики для отчёта** — список пуст при открытии, собери отчёт сам:
- «+ Добавить метрику» → модальное окно: выбираешь метрику, задаёшь её
  параметры (поля строятся автоматически: числа, даты-календари, выбор),
  «Добавить»;
- одну метрику можно добавлять **несколько раз с разными параметрами**
  (например, «зависшие» с порогом 14 и 45 дней);
- **↑ ↓** — порядок (= порядок в отчёте), **✎** — изменить параметры,
  **✕** — убрать из отчёта;
- пустой список = запустятся все метрики с параметрами по умолчанию.

**Результаты**: прогресс и лог в окне, отчёт рендерится ниже — графики
интерактивные (тултипы, легенда), длинные таблицы свёрнуты.
**Скачать HTML** — самодостаточный офлайн-отчёт (открывается двойным
кликом, графики живые); **Скачать Excel** — по листу на каждую таблицу.

## CLI

```bash
.venv/bin/python main.py --project CURATOR --jira-type apache
.venv/bin/python main.py --project PROJ --jira-type jira --skip-fetch          # по имеющейся выгрузке
.venv/bin/python main.py --project PROJ --jira-type jira --max-issues 200      # обрезка (тест)
.venv/bin/python main.py --project PROJ --jira-type jira --resume              # продолжить прерванную выгрузку
.venv/bin/python main.py --project PROJ --jira-type jira --fresh               # стереть прогресс, качать заново
.venv/bin/python main.py --project PROJ --metrics 'stale_issues(stale_days=45),completed_by_assignee(date_from=2025-01-01)'
.venv/bin/python main.py --list-metrics      # что зарегистрировано, с параметрами
.venv/bin/python main.py --check-metrics     # самопроверка всех метрик
```

Параметры метрик в CLI — строками в скобках через запятую; типы приведутся
автоматически. Полный `--help` покажет все флаги (даты, комментарии, ретраи).

## Метрики

Встроенные: обзор проекта; активность по неделям и по исполнителям (с фильтром
по датам); выполнено по исполнителям (за период по дате выполнения); зависшие
задачи (порог настраивается); дисциплина (мимо статусов, без исполнителя);
циклы задач и сводка времени жизни; переоткрытия и их сводка.

**Добавить свою метрику** — один python-файл в `metrics/`, без правок
основного кода: инструкция в [metrics/README.md](metrics/README.md) (в том
числе для нейросети — можно попросить её написать метрику по этому файлу).
Проверка: `python main.py --check-metrics`.

## Тесты

Автотесты (pytest) — без сети: HTTP-слой Jira имитируется мини-стендом,
проверяется всё вплоть до цикла «выгрузка упала → продолжилась → результат
равен цельному прогону».

**Linux / macOS:**

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

**Windows (CMD / PowerShell):**

```bat
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest
```

Если что-то упало — пришли лог pytest целиком (`pytest` печатает причину
по каждому сценарию). Разовые проверки руками кладутся в `.for_agent/test/`,
не в `tests/`.

## Настройки (.env)

Скопируй `.env.example` → `.env` и заполни: токены `JIRA_TOKEN` /
`JIRA_DELTA_TOKEN` (или суффикс `_PAT`), адреса корпоративных Jira, при
нужности — задержки/ретраи fetch и `WEB_PORT`. Ничего больше заполнять не
нужно: тип jira выбирается в интерфейсе/CLI (`--jira-type`).

## Большие проекты

Выгрузка идёт страницами по 100 задач, changelog — батчами, всё пишется
потоково в JSONL (`data/raw/<проект>/`) — память не зависит от объёма
(~136k задач ≈ 40–60 мин). Комментарии по умолчанию не выгружаются.
В web/HTML таблицы показываются до 200 строк (полные — в Excel), лист Excel —
до 5000 строк.

Прогресс и возобновление: во время выгрузки всё лежит в `_partial/`
с чекпоинтом после каждой страницы/пачки — упавшая выгрузка продолжается
с места остановки (web: «Продолжить», CLI: `--resume`), а старая целая
выгрузка в корне папки не повреждается. Если сервер Jira обрезает глубину
пагинации (лимит `jira.search.max.results`), диапазон дат автоматически
делится на окна — выгрузка не обрывается молча.

## Проблемы

- **Порт занят** (остаточный процесс прошлого запуска): `pkill -f src.web.app`
  (Linux) или закрой старое окно `start.bat` (Windows) и запусти заново.
- **Не грузятся файлы метрик** — список ошибок показывается в интерфейсе
  красным; детали: `python main.py --check-metrics`.
