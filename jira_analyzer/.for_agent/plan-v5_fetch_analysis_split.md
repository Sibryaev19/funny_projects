# План: v5 — разделение выгрузки и анализа в web

Статус: **done** (реализовано и проверено e2e 2026-11-13)
Дата: 2026-11-13

## Цель
В web-интерфейсе явные две зоны: «Выгрузка» (скачать задачи проекта в свою
папку data/raw/) и «Анализ» (выбрать одну из скачанных папок в таблице,
накидать метрики, запустить пересчёт без хождения в Jira). Скачал один раз —
анализируй сколько угодно.

## Принятые решения (шаг 1)
- Папки плоские: data/raw/<КЛЮЧ_ПРОЕКТА>, тип jira живёт в fetch_summary.json
  (он его уже пишет: jira_type, jira_url, fetched_at, counts.issues,
  counts.changelog_events — читать только эти файлы, пересчитывать нечего).
- Коллизия ключа между двумя Jira: список выгрузок показывает тип каждой;
  перед fetch UI предупреждает «в папке уже выгрузка из <тип> — перезапишем?».
  Одинаковый тип = тихая перезапись (это и есть «обновить»).
- Список выгрузок — таблица с деталями: ключ, тип jira, задач, событий,
  дата выгрузки. Выбор кликом по строке (подсветка).
- Никаких кнопок удаления/обновления: перезапись = повторный fetch, удаление
  вручную. (Решение пользователя.)
- CLI не трогаем: --skip-fetch уже даёт то же самое руками.

## Изменения
### Бэкенд (мало)
- `pipeline.py`: вынести fetch-шаг в отдельную функцию `run_fetch(opts)`;
  `PipelineOptions.fetch_only: bool` — задание «только выгрузка».
- `jobs.py`: без структурных изменений — start_job(opts) ветвится по
  fetch_only (run_fetch вместо run_pipeline); snapshot переиспользуется.
- `app.py`:
  - `GET /api/downloads` — скан data/raw/*/issues.jsonl + чтение
    fetch_summary.json (без него: имя + mtime, метки «—»);
  - `POST /api/fetch` — запускает fetch-only задание (ключ проекта, тип jira,
    даты, лимит, комментарии);
  - лёгкая санитизация имени проекта/папки на обоих POST-эндпоинтах
    (^[A-Za-z0-9][A-Za-z0-9._-]*$ — путь строится из этого имени);
  - `/api/run` остаётся как есть (skip_fetch: true = анализ папки).

### Фронтенд (вся работа)
- `index.html`: карточка «1 · Выгрузка» (ключ, тип jira, даты, лимит,
  комментарии → «Скачать задачи») и карточка «2 · Анализ» (таблица выгрузок
  + текущий блок «Метрики для отчёта» → «Запустить анализ» по выбранной
  строке). Галочка «анализ имеющейся выгрузки» удаляется — её заменяет зона 2.
- Прогресс-карточка одна на оба вида заданий; после fetch — обновить таблицу.
- Анализ без выбранной строки — alert. Пустой data/raw — подсказка «начни
  с выгрузки».
- Таблица обновляется при загрузке страницы и после завершения fetch.
