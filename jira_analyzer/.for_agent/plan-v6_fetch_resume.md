## Цель
Выгрузка большого проекта (136k, 40–60 мин) не теряет данные при падении,
продолжается с места остановки, управляется из web. Плюс: защита пагинации,
валидация JQL-дат, зависимости под Python 3.11–3.13, папка тестов pytest.
Web-first. Без дельты/PDF/новых метрик (MVP). Параллельные выгрузки НЕ
запрещаем (решение пользователя 2026-11-13: на совести пользователя).

## Решения (обсуждены и приняты 2026-11-13)
- Fetch пишет в `data/raw/<КЛЮЧ>/_partial/`, корень папки не трогается до
  успеха; коммит = атомарное перемещение файлов + `fetch_summary.json`.
- `state.json` рядом: фаза (issues/changelog/comments), байтовые офсеты
  файлов, счётчики, суммарные total из API, отпечаток параметров (проект,
  jira_type, даты, max_issues, with_comments, skip_changelog, хэш
  fields.json). Запись после каждой страницы задач и каждой пачки
  changelog/комментариев, атомарно (tmp+rename).
- Возобновление: режем файлы по офсетам из state (убирает недописанный хвост
  и дубль последней пачки), продолжаем. Работает после падения, закрытия
  окна, рестарта сервера. CLI получает бесплатно (--resume / --fresh).
- Триггер резюма — спрашиваем в UI: «Продолжить с задачи N» / «Начать заново»
  (с confirm). Отпечаток не совпал → предложить только «Начать заново».
  API: POST /api/fetch {resume: bool}; resume=false при наличии partial → 409
  (выбор всегда явный; CLI: нет флагов при partial → ошибка с подсказкой).
- Кнопка «Стоп» у задания выгрузки: флаг Job, проверяется между страницами и
  пачками → статус stopped, _partial сохранён. Для заданий анализа — не
  показывается. POST /api/job/{id}/stop.
- Пагинация: пустая страница при given<total — не «конец», а WARNING и
  автоматическое переключение на окна по created (рекурсивное деление
  диапазона), сквозной дедуп ключей. Ответ API Apache проверен 2026-11-13:
  startAt за границей total отдаёт пусто без ошибки.
- Валидация дат fetch (YYYY-MM-DD, from<=to): web-эндпоинты → 400, fetch-слой
  → ValueError. Ключ проекта в JQL — в кавычках.
- Дедуп задач по ключу при коммите (последняя строка выигрывает) — лечит
  сдвиги пагинации на живом сервере между сессиями резюма.
- Зависимости: ограниченные диапазоны с поддержкой 3.11–3.13:
  pandas>=2.2,<3 · pydantic>=2.6,<3 (явно, используется напрямую) ·
  fastapi, uvicorn, requests, openpyxl — с верхними границами.
  Dev: requirements-dev.txt (pytest, httpx для TestClient). Локально гоняем
  на 3.12; 3.11/3.13 покрыты выбором границ (честно: не прогоняем).
- Тесты: папка tests/, pytest, полностью без сети (фейковый HTTP-клиент),
  раздел «Тесты» в README.

## Попутный баг (найден при проектировании, показан пользователю)
tables.py читает changelog.jsonl плоским флэтеном, а fetch дописывает ПОЛНУЮ
историю задачи после урезанной (>100 событий) → события таких задач
учитываются дважды. Фикс: при чтении «последняя запись по ключу выигрывает»
(и для comments-записей — единообразно).
