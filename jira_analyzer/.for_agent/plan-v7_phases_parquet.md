## Мелкие задачи (SDD: каждая = код + проверка)

### T1. Фазы выгрузки: задачи / история / обе
- FetchOptions (+pipeline): `phases: "both" | "issues" | "changelog"`.
- run.py: фаза issues как сейчас; фаза changelog-only берёт ключи из
  УЖЕ скачанного issues.jsonl папки (без ключей качать нечего → понятная
  ошибка); коммит changelog-only НЕ трогает issues.jsonl (мержит только
  свой файл, дедуп по ключу как есть).
- CLI: `--phases issues|changelog|both` (default both).
- fetch_summary.json: записать фазы выгрузки (для UI/анализа).
- Проверка: выгрузка issues-only в новую папку; changelog-only поверх
  существующей (issues.jsonl не изменился байтово; changelog.jsonl появился);
  resume цикл с фазами.

### T2. Web: выбор фаз + «докачать историю»
- Зона «Выгрузка»: чекбоксы «Задачи» / «История изменений» (хотя бы одна).
- Таблица «Анализ»: у папки без changelog.jsonl (или с phases=issues) —
  кнопка «Докачать историю» → fetch-only задание с phases=changelog.
- Проверка: браузером — старт issues-only, докачка истории, Стоп/Продолжить.

### T3. data/processed + parquet-кеш

  усмотрение; pyarrow в requirements).
- load_tables: если кеш свежее raw (mtime+size всех jsonl) — читать parquet;
  иначе пересобрать один раз и записать. Кеш-отсутствие не ошибка.
- Служебная папка — в .gitignore вместе с data/ (проверить текущий gitignore).
- Проверка: время повторного анализа на CURATOR (8523 события) падает
  заметно; правка jsonl → пересборка.
