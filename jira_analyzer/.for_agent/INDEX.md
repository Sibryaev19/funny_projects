## Проект
**jira_analyzer** — модульная система анализа работы разработчиков по данным Jira
(корпоративный аудит; публично — без упоминания организации).
Реализовано: v1 пайплайн (fetch → analysis → отчёты, этапы 0–5), **v3 компонентная
архитектура метрик** и **v4 параметры метрик, запрашиваемые у пользователя
(2026-11-13, done — детали: plan-v4_metric_params.md + context.md «Задача v4»)**.
Теперь: fetch (батчи, стриминг JSONL, 2 корпоративные Jira по префиксам .env) →
метрики-компоненты (metrics/, автоподхват, декларации Param) → экземпляры
{metric_id, params} → блоки BlockSpec (pydantic) → web (FastAPI :8765,
модалка выбора метрик, echarts-графики, сворачивание блоков) и офлайн HTML-отчёт
(тот же JS-рендер инлайном) + Excel (табличные блоки). matplotlib удалён.

## Как запустить
- Windows-скрипты: `setup.bat` (установка, бывший start.bat) и `start.bat`
  (запуск web-интерфейса в терминале со ссылкой)
- Установка руками: `python setup/start.py`; пользовательская инструкция — README.md
- CLI: `python main.py --project CURATOR --jira-type apache`
  (`--metrics 'stale_issues(stale_days=45),overview'`, `--list-metrics`,
  `--check-metrics`; `--stale-days` больше нет; прерванная выгрузка:
  `--resume` продолжить / `--fresh` заново)
- Автотесты: `pip install -r requirements-dev.txt`, `python -m pytest`
  (без сети, 44 шт: tables/client/пагинация/resume-цикл/reports/web)
- Web: `python -m src.web.app` → http://127.0.0.1:8765 (порт: WEB_PORT в .env).
  **Две зоны** (v5): «1 · Выгрузка» — fetch в data/raw/<ключ> (перезапись =
  обновление; предупреждение при смене типа Jira); пишется через _partial/
  с чекпоинтами, кнопка ⏹ Стоп, баннер «Продолжить/Начать заново» (v6).
  «2 · Анализ» — таблица скачанных папок (ключ, jira, задач, событий, дата)
  → выбор строки → метрики → пересчёт без fetch.
  Метрики: «+ Добавить метрику» (модалка), у выбранных ✎ (изменить), ↑↓
  (порядок), ✕.
- Тест без токена: jira-type apache (проект CURATOR/RAT, выгрузка в data/raw/)

## Метрики-компоненты (главное для нового чата)
- Каждая метрика = .py-файл в **metrics/**, класс-наследник BaseMetric
  (id/label/description + build(tables, opts) -> список блоков). Автоскан при старте.
- Параметры метрики: `params = [Param(...)]` — форма в web-модалке и CLI
  `id(имя=значение)` строятся из декларации; в build() значения через
  `opts.get("имя")`. Инструкция — metrics/README.md, раздел 7.
- Блоки: table / bar / line / pie / list (pydantic, src/components/blocks.py);
  строятся хелперами self.table/self.bar/self.pie/... — JSON-safe автоматически.
- **metrics/README.md — подробная инструкция для человека/нейросети**: схемы таблиц,
  хелперы, правила, параметры, примеры. Новую метрику просить у нейросети по этому README.
- Тест метрик: `python main.py --check-metrics` (юнит-тесты params + все метрики).
- Хочешь новый ТИП блока → blocks.py (модель) + blocks.js (рендерер), см. README.

## Важно для нового чата
- Токены: .env секция ТОКЕНЫ (JIRA_TOKEN / JIRA_DELTA_TOKEN, суффиксы _TOKEN/_PAT).
- ~136k задач в корпоративном проекте → батчи, JSONL-стриминг, комментарии off по умолчанию.
- **Выгрузка продолжаема (v6)**: _partial/ + state.json (байтовые офсеты,
  отпечаток параметров); JSONL читается «последняя запись по ключу» — дедуп
  не убирать. Параллельные задания web не ограничены (решение пользователя).
- ECharts вендорен в src/web/static/vendor/ (сеть на работе закрыта, CDN не использовать).
- payload web/отчёта режет таблицы до 200 строк (полные в Excel); Excel лист <=5000 строк.
- «Скачать HTML» — attachment (скачивание), офлайн-рендер отчёта проверен.
- Фоновый web-сервер прошлой сессии может держать порт (WEB_PORT в .env, дефолт 8765):
  если bind fail — `pkill -f src.web.app` и запустить заново (pkill и запуск
  сервера не совмещать в одной bash-строке — pkill убьёт команду по подстроке).
- Архитектура v3+v4 (компоненты, блоки, параметры, рендер) — context.md;
  тест данных для харнесса/прогонов — CURATOR в data/raw/ (полная выгрузка 724
  задачи + 8523 события — эталон после v6-resume прогона, jira-type apache).
