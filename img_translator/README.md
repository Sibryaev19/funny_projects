# img_translator — визуальный канал передачи данных

Передача файлов **через экран**: передатчик пакует файлы в zip и рисует их
мерцающими цветными кадрами (в браузере, а в перспективе — механизмами игры),
приёмник снимает область экрана, распознаёт кадры и собирает файлы обратно.
Передача проверена бит-в-байт на объёмах до 3.4 МБ.

Две части:
- **передатчик** (`server/`) — web-приложение, тестовый инструмент;
- **приёмник** (`receiver/`) — отдельная консольная программа.

Обе части связаны только пакетом `protocol/` (протокол + распознавание).

---

## 1. Требования

- **Python 3.10+**.
  - Windows: ставить с python.org, при установке отметить
    **«tcl/tk and IDLE»** (нужен для диалога выбора файлов).
  - Linux: tkinter обычно уже есть (`sudo apt install python3-tk`, если нет).
- Экран и способ захвата:
  - **Windows / X11 Linux**: ничего дополнительно, захват через `mss`.
  - **Linux + Wayland (GNOME)**: нужен `gstreamer1.0-tools` с плагином
    `pipewiresrc` (на Ubuntu ставятся так:
    `sudo apt install gstreamer1.0-tools gstreamer1.0-plugins-base gstreamer1.0-good`).
    При первом запуске появится системный диалог «поделиться экраном» —
    согласие запоминается (restore_token), дальше диалогов не будет.

## 2. Установка (в venv, систему не засоряем)

> **Windows без Python в PATH** — см. [windows/README.md](windows/README.md):
> там `install.bat` (сам найдёт Python, создаст `.venv`, поставит зависимости)
> и bat-файлы для запуска всего одним нажатием.

### Windows

```bat
cd C:\path\to\img_translator
py -3 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### Linux

```bash
cd ~/path/to/img_translator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 3. Проверка установки

```bash
python tests/run_all.py
```

Прогоняет 4 неинтерактивных теста (~10 секунд):
- `test_encoder` — протокол: кодирование→декодирование во всех палитрах
  (2/4/8/16 цветов), контроль CRC, отказ на кривых сетках;
- `test_vision` — распознавание: синтетические «скриншоты» с шумом,
  случайным положением и нецелым масштабом ячеек;
- `test_e2e_receiver` — полный цикл приёма без экрана (FakeCapture):
  кадры → сборка → zip → распаковка, таймаут на мусоре;
- `test_picker_process` — tkinter в отдельном процессе (механика диалога
  выбора файлов передатчика).

Отдельно, руками (в `tests/`):
- `test_pdeathsig.py` — дочерний процесс умирает вместе с родителем (Linux);
- `limits_probe.py` — **интерактивный**: меряет безопасные пределы твоего
  экрана (цветов × размер ячейки). На Windows запускается так же
  (`python tests/limits_probe.py`), mss-захват диалогов не требует.

## 4. Передача (web-передатчик)

```bash
# в активированном venv
uvicorn server.app:app --reload
```

Открыть **http://127.0.0.1:8000**. Порядок:

1. **«Добавить»** — откроется окно выбора: двойной клик — вход в папку,
   Ctrl/Shift — мультивыбор файлов и папок вперемешку, «ОК».
2. Настройки кадра: **Сетка W×H** (ячеек), **Ячейка N px**, **Цветов**.
   Подпись «≈ N байт/кадр» показывает ёмкость текущей конфигурации.
   Слева на canvas — предпросмотр кадра (фиолетовая рамка, чёрные маркеры,
   голубая полоса заголовка, поле данных в цветах палитры).
3. **«Передать»** — сервер пакует выбранное в zip, режет на кадры, кадры
   начинают сменяться на canvas. В статусе: «кадров: N/M».
4. **«Пауза между кадрами, мс»** — сколько кадр висит на экране.
   **«цикл»** — держать включённой: кадры крутятся, пока приёмник не соберёт всё.
5. **«Во весь экран»** — рекомендуется: кадр крупнее, меньше шансов на брак.

## 5. Приём (консольный приёмник)

```bash
python -m receiver.main --grid 256 192 --colors 16 --fps 5
```

**Важно: сетка и число цветов приёмника должны совпадать с передатчиком** —
приёмник сверяет их с заголовком кадра и честно ругается при несовпадении.

Что произойдёт:
1. (Linux/Wayland) один раз появится диалог «поделиться экраном» — подтвердить.
2. Приёмник снимает весь экран и **сам находит рамку кадра** (передатчик
   должен уже мерцать). Не нашёл — откроются «ножницы»: растяни рамку
   мышью по кадру (Esc — отмена).
3. В консоли: `кадров: N/M, осталось: K`. Кадры собираются по номерам,
   битые переснимаются автоматически.
4. Когда собраны все: проверка zip → распаковка в `received/<дата-время>/`.

Флаги:

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--grid W H` | 128 96 | сетка, **как на передатчике** |
| `--colors N` | 16 | 2/4/8/16, **как на передатчике** |
| `--fps F` | 4 | снимков в секунду (5–6 рекомендовано) |
| `--region x,y,w,h` | нет | область вручную (координаты экрана) |
| `--out DIR` | `received/<дата-время>/` | куда распаковать |
| `--timeout SEC` | 0 | 0 = без лимита (Ctrl+C — прервать) |
| `--capture auto\|mss\|wayland` | auto | auto: Wayland→портал, иначе mss |
| `--debug` | выкл | сохранять бракованные снимки в /tmp/imgtr_debug |

## 6. Как рассчитать параметры (главное)

### 6.1. Правило размера ячейки

Единственное измеренное требование к надёжности:

> **физический размер ячейки на экране (pitch) ≥ 3 px — передача без ошибок.**
> Работает вплоть до ~2.2 px; ниже ~1.5 px рамка схлопывается и приём невозможен.

pitch = «Ячейка» на странице × **масштаб отображения** (во сколько раз браузер
во весь экран увеличивает пиксели страницы).

Пример: ячейка 10 px, масштаб 1.65 → pitch 16.5 px — огромный запас.
На Windows с масштабом 150% в fullscreen — масштаб 1.5.

Точные пределы своего экрана меряются стендом: `python tests/limits_probe.py`.

### 6.2. Сколько влезает в кадр

Точная цифра всегда видна на странице («≈ N байт/кадр») или через API:
`GET /api/capacity?w=W&h=H&palette=16`.

Оценка вручную: `ёмкость ≈ (W−6)×(H−6)×k/8 − 1.5 КБ`, где k = log2(число цветов).

### 6.3. Время и кадры передачи

1. zip-архив ≈ размер исходных данных (сжатие deflate).
2. **кадров = ceil(объём zip / ёмкость кадра)**.
3. **полный цикл показа = кадров × пауза** (при паузе 500 мс и 444 кадрах — 222 с).
4. Планируй **1.5–2 цикла** на приём (часть снимков ловит момент смены кадра
   и переснимается). При `--fps 5` и паузе 500 мс — каждый кадр снят ~2.5 раза.

### 6.4. Пауза и fps

> **пауза ≥ 2.5 × (1000 / fps)** — золотое правило.

- fps 5 → пауза ≥ 500 мс (безопасно), 400 мс (на грани, работает);
- fps 3 → пауза ≥ 1000 мс;
- fps 6 (максимум потока) → пауза ≥ 400 мс.

### 6.5. Готовые конфигурации

Пример для экрана 3840×2160, браузер во весь экран (масштаб 1.65):

| Сетка | Ячейка | Байт/кадр | Скорость при паузе 500 мс |
|---|---|---|---|
| 128×96 | 10 | 5 355 | ~10 КБ/с |
| 152×112 | 10 | 7 591 | ~15 КБ/с |
| 192×144 | 8 | 12 667 | ~25 КБ/с |
| 256×192 | 6 | 23 051 | ~45 КБ/с |
| 320×240 | 5 | 36 507 | ~71 КБ/с |
| 384×288 | 4 | 53 035 | ~104 КБ/с |
| 512×384 (макс) | 3 | 95 307 | ~186 КБ/с |

Для другого экрана: подбери ячейку так, чтобы `сетка × ячейка` влезала в
пол-экрана по меньшей стороне, а pitch был ≥ 3 px, затем сверься со
значением «≈ N байт/кадр» на странице.

### 6.6. Пример расчёта «передать 10 МБ»

1. Объём zip ≈ 10 МБ (если данные уже сжатые).
2. Берём 384×288×16цв: 53 035 Б/кадр → 10 485 760 / 53 035 ≈ **198 кадров**.
3. Цикл: 198 × 0.5 с ≈ 99 с; приём ≈ 1.5 цикла ≈ **2.5 минуты**.

## 7. Устранение неполадок

| Симптом | Причина и что делать |
|---|---|
| Диалог «поделиться экраном» | Норма на Wayland, один раз. Согласие запоминается. Сбросить: удалить файл `~/.config/img_translator/portal_restore_token` |
| `маджента-рамка не найдена` | Передатчик не мерцает (не нажал «Передать»?) или окно кадра перекрыто другим окном |
| `маджента-область слишком мала` (изредка) | Снимок поймал момент перерисовки — приёмник переснимет сам |
| `ячейка слишком мелкая` | Ячейка × масштаб < ~2.5 px: увеличь «Ячейку» на странице или уменьши сетку |
| `палитра в кадре — N, ожидалось M` | Число цветов приёмника ≠ передатчика |
| `размер в заголовке не совпал` | Сетка приёмника ≠ передатчика |
| `CRC не сошёлся` в прогрессе | Кадр прочитан грязно — приёмник сам переснимет; если повторяется массово, включи `--debug` и увеличь ячейку |
| Windows: кракозябры в консоли | `set PYTHONUTF8=1` перед запуском |
| Windows: брандмауэр спросил про python | Разрешить (сервер слушает только 127.0.0.1) |
| Windows: `ModuleNotFoundError: tkinter` | Переустановить Python с галочкой «tcl/tk and IDLE» |

## 8. Что должна рисовать игра (перенос протокола)

Протокол v3 полностью описан и реализован в `protocol/encoder.py`
(единственный источник правды). Игра должна:

1. Рисовать сетку W×H прямоугольников цветов из `PALETTES` (RGB-коды там же).
2. Соблюдать разметку кадра: маджента-рамка (255,0,255) толщиной 2 ячейки
   по периметру; белая тихая полоса 1 ячейка; ч/б маркеры 7×7 в трёх углах
   (шаблон `_FINDER_PATTERN`); заголовок чёрно-белыми битами в строках под
   верхними маркерами; полезная нагрузка — k = log2(N) бит на ячейку.
3. Кодирование байтов → кадры уже написано (`encode_frames`) — игре остаётся
   вызывать его и рисовать результат, либо повторить логику по докстрингу.
4. Держать каждый кадр на экране заметное время (пауза) и менять кадры целиком.

Приёмник совместим с любым источником кадров: браузер, игра, второй монитор.

## 9. Структура проекта

```
protocol/encoder.py   протокол: палитры, кадры, CRC, декодер
protocol/vision.py    распознавание кадров на скриншоте
server/               web-передатчик (FastAPI + страница без JS-библиотек)
receiver/             приёмник: CLI, захват (mss/портал), ножницы, сборка
tests/                тесты + стенд пределов + run_all.py
received/             сюда приёмник складывает результат
.for_agent/           рабочие заметки разработки (не нужна для запуска)
```
